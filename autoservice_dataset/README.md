# Синтетические диалоги для подбора автосервиса

Набор русскоязычных диалогов с разметкой после каждой реплики. Слот — поле с извлечённым сведением: например, автомобиль, симптом или формат помощи.

Объём и результаты проверок записаны в `manifest.json` и `quality_report.json`. Перед использованием проверяйте статус проверки смысла разметки: автоматическая проверка структуры и проверка другой моделью не заменяют экспертную оценку тестовых ответов.

## Файлы

- `train.jsonl` — 1 000 обучающих диалогов.
- `test.jsonl` — 200 тестовых диалогов.
- `manifest.json` — версия исходной схемы, способ генерации, число реплик и контрольные суммы файлов.
- `quality_report.json` — результаты проверок, распределение сценариев, заполнение слотов и ограничения проверки.
- `schema/` — копия исходной схемы и каталога услуг из зафиксированного коммита.
- `generation/` — задания генератору, инструкции для модели, скрипты, исходные ответы и результаты проверки.

JSONL — текстовый файл, в котором каждая строка содержит один полный JSON-объект. Пример чтения:

```python
import json
from pathlib import Path

for line in Path("train.jsonl").read_text(encoding="utf-8").splitlines():
    dialogue = json.loads(line)
    for turn in dialogue["turns"]:
        print(turn["role"], turn["text"], turn["slots_after_message"])
```

## Разметка

`slots_after_message` содержит полное состояние известных слотов. Неупомянутые сведения отсутствуют. `unknown` означает явно выраженное незнание или существенную для подбора неопределённость; `conflicting` — неразрешённое противоречие. Изменение состояния автомобиля во времени не считается противоречием.

`evidence` содержит источники новых или изменённых значений текущей реплики. `raw_text` — дословная цитата, `interpretation` — значение слота. `kind` различает наблюдение, предположение, чужое заключение и заказ работы. `time_scope` различает прошлое, настоящее и неуказанное время. `supersedes` связывает новое значение с предыдущим сообщением, на котором основано заменяемое значение. Полная история остаётся в прежних репликах.

Ассистент не создаёт пользовательских фактов. После его вопроса состояние сохраняется, а `evidence` остаётся пустым. Гипотезы и чужие заключения не означают подтверждённую неисправность или заказ ремонта. Значения `known_service` ссылаются на существующие записи каталога. При распознавании этих идентификаторов используйте полный `schema/catalog.json`: часть услуг встречается только в тестовых диалогах.

Общие слоты используются с учётом соответствий из `tree.json`; отдельные дубликаты слотов поддеревьев не вводятся. Формат результата подбора мастерской не добавляется к состоянию слотов.

## Проверки и воспроизведение

Для базовой проверки достаточно стандартной библиотеки Python:

```bash
python generation/validate.py
python generation/audit.py
```

Проверяются структура, допустимые значения, ссылки на сообщения, дословность цитат, сохранение состояния, отсутствие новых фактов в вопросах ассистента и количество диалогов. Поиск близких копий сравнивает тройки последовательных слов пользовательских реплик; сведения об автомобиле и городе предварительно заменяются общей меткой. Метод и порог указаны в отчёте. Такой поиск не доказывает отсутствие всех смысловых повторов.

Сценарии распределяются по 25 направлениям и разным видам обращения. В исходных заданиях генератору явные заказы распределялись по разным подмножествам каталога для обучения и теста. При исправлении разметки используется весь каталог; фактическое пересечение идентификаторов услуг указано в отчёте. Сложность, направление и запланированный тип обращения сохранены в `generation/plans.json`; фактические значения слотов подсчитаны отдельно в отчёте.

Для новой генерации нужен `httpx` и доступ к API Yandex AI Studio. Скрипты читают `YANDEX_CLOUD_FOLDER_ID` и `YANDEX_CLOUD_API_KEY` из `.env` в родительском каталоге набора. Ключи в поставку не входят. Запуск вызывает платный API и возобновляет работу по сохранённым партиям:

```bash
python generation/generate.py --workers 5
python generation/review.py --all --workers 5
```

Проверка смысла разметки выполняется отдельными запросами без скрытого сценария генератора: весь набор проверяет Qwen3.6 35B, а все тестовые диалоги и каждый десятый обучающий и спорные примеры дополнительно проверяет DeepSeek V4.1 Flash. В отчёте указаны её фактический объём и замечания. Исходные ответы модели сохраняются; ссылки на прошлые значения и накопительное состояние строятся скриптом. Компактные имена полей промежуточного ответа разворачиваются в полный формат. Несколько источников одного текстового слота в одной реплике объединяются с сохранением охватывающей их дословной цитаты.

Повторный запуск модели может дать другие формулировки: фиксированный план не делает генерацию модели детерминированной. Для проверки переданного результата используйте сохранённые данные и контрольные суммы.

Тестовый набор следует хранить отдельно от обучения и настройки модели. Если нужна выборка для настройки, выделите её из обучающего набора. До экспертного утверждения тестовые метки не следует считать безусловно достоверными эталонными ответами.
