Создай по одному русскоязычному диалогу подбора автосервиса на каждое задание. Разметь факты ПОСЛЕ КАЖДОЙ пользовательской реплики. Только JSON-объект {"dialogues":[...]}.

Формат каждого диалога: {"case_id":123,"turns":[{"role":"user","text":"При торможении тянет вправо.","updates":[{"s":"intent","q":"При торможении тянет вправо.","v":"complaint"},{"s":"main_symptom","q":"При торможении тянет вправо.","v":"При торможении тянет вправо."},{"s":"observed_context","q":"При торможении","v":"braking"}]},{"role":"assistant","text":"В каком городе искать сервис по тормозам?","updates":[]},{"role":"user","text":"В Уфе.","updates":[{"s":"search_area","q":"В Уфе.","v":"Уфа"}]}]}.

В updates используются короткие ключи: s — имя слота; q — ДОСЛОВНЫЙ фрагмент текущей реплики; v — значение. Только новые/изменённые слоты. Не пиши slot/raw_text/interpretation, полные состояния и ссылки: скрипт построит их сам. Ассистент всегда updates=[]. Не заполняй слот из скрытого задания до его явного появления в речи пользователя.

Сделай target_turns реплик, строго чередуя user/assistant и начиная с user. При target_turns=3: задача и часть фактов сразу; один полезный вопрос; ответ. Для сложного сценария можно 5 вместо 3. Предпочитай закончить user. Итоговый пересказ ассистента не нужен. Разные стиль, порядок сведений и длина; не повторяй универсальный опрос машины и города. vehicle_hint/city_hint помогают разнообразию; машину замени, если она несовместима с работой. Все данные вымышленные, без телефонов, VIN и госномеров.

Правила разметки:
1. Допустимы только слоты и значения приложенной схемы. Текстовые поля содержат конкретные сведения, а не free_text. known_service — реальный id из предложенных услуг ТОЛЬКО при явном заказе. Жалоба/гипотеза не заказ ремонта. Просьба проверить не заказ замены. Если нужной диагностической услуги среди id нет, не заполняй known_service.
2. intent: known_service — конкретный заказ; complaint — наблюдаемая проблема; desired_result — цель без определенной работы и жалобы; external_conclusion — обращение с чужим заключением; multiple — несколько задач; event — обращение о событии. Пустое приветствие не unknown.
3. main_symptom содержит ВСЕ наблюдаемые симптомы. При уточнении новое значение сохраняет прежние симптомы и их время. Обе независимые проблемы сохраняются при выборе приоритета. Не добавляй гипотезу/чужой диагноз как наблюдаемый факт. affected_item — названный предмет работы. previous_diagnosis: user_guess для предположения; reported_conclusion для слов сервиса; document_quote для цитаты документа; none_reported только при явном отрицании прежних проверок.
4. Не угадывай топливо по модели, объёму двигателя, свечам и педалям. powertrain только из явных слов о бензине/дизеле/газовом оборудовании/гибриде/электромобиле. gearbox только из явных слов о типе коробки. «Автомат, точнее не знаю» — automatic_unspecified. «На холодную» не stationary; context=stationary только «на месте/холостых/пока стоит». Незнание времени появления не current_state=unknown.
5. unknown — явно не знает, conflicting — две несовместимые версии одного факта без разрешения. Явное исправление заменяет значение; смена состояния во времени не conflicting. При смене current_state история симптома остаётся в main_symptom. Если исправлена ошибочная жалоба, обнови все затронутые поля.
6. Обычные источники имеют вид observation и время unspecified. Для main_symptom/current_state/observed_context и intent=complaint/multiple время по умолчанию current; для event — past. known_service и intent=known_service — service_request/unspecified; previous_diagnosis=user_guess — hypothesis/unspecified; reported_conclusion/document_quote — reported_diagnosis/unspecified. Если это правило НЕ подходит, добавь k (observation/hypothesis/reported_diagnosis/service_request) и t (past/current/unspecified). Например прошлый симптом имеет t="past". В остальных случаях не выводи k/t.
7. Каждый явно сообщённый применимый факт размечается: автомобиль, город, топливо, коробка, предмет работы, наблюдения и их контекст. Для названного автомобиля сохраняй известный год; если год не помнит, не стирай известную модель. Отсутствие упоминания не отрицание.

Ассистент: использует известное, задаёт только полезные для подбора вопросы и допускает незнание. Не требует догадки о причине или названия неисправной детали. Не ставит диагноз, не назначает ремонт по симптому. Не обещает запись, цену, наличие или найденную мастерскую. Явный заказ не переводит в диагностический опрос. Не спрашивает о выезде для каждой обычной работы. Для ключей проверка документов — у исполнителя, без утверждения права собственности. Никаких инструкций опасного самостоятельного ремонта.
