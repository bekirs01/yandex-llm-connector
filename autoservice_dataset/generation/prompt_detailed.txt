Создай синтетические русские диалоги владельца машины и помощника подбора автосервиса по заданиям. Только JSON-массив объектов. По одному объекту на каждое задание в том же порядке.
Формат объекта: {"case_id":число,"turns":[{"role":"user","text":"...","updates":[{"s":"intent","q":"точный фрагмент этой реплики","v":"complaint","k":"observation","t":"current","supersedes":null}]},{"role":"assistant","text":"...","updates":[]},...]}
updates содержит ТОЛЬКО новые/измененные значения. supersedes — номер предыдущей реплики (считая все реплики с 1), заменяемой при исправлении, иначе null. Фрагмент строго подстрока text, с тем же регистром и пунктуацией. Значения слотов — строки. Скрипт накопит полное состояние и построит evidence. Начни user, строго чередуй роли. 3–9 реплик, заканчивай user или коротким итогом assistant. Разные длина, порядок сведений, стиль и структура; не повторяй универсальный опрос автомобиль-город. Не добавляй поля, не пиши markdown.
Пример: {"case_id":123,"turns":[{"role":"user","text":"При торможении тянет вправо.","updates":[{"s":"intent","q":"При торможении тянет вправо.","v":"complaint","k":"observation","t":"current","supersedes":null},{"s":"main_symptom","q":"тянет вправо","v":"При торможении тянет вправо.","k":"observation","t":"current","supersedes":null},{"s":"observed_context","q":"При торможении","v":"braking","k":"observation","t":"current","supersedes":null}]},{"role":"assistant","text":"В каком городе искать сервис для проверки тормозов?","updates":[]},{"role":"user","text":"В Уфе.","updates":[{"s":"search_area","q":"В Уфе.","v":"Уфа","k":"observation","t":"unspecified","supersedes":null}]}]}
Допустимы только общие слоты из приложенной схемы. Не пиши free_text/catalog_id буквально: используй текст или существующий id услуги. Не заполняй неупомянутые слоты. unknown только при явном незнании. В main_symptom сохраняй все наблюдения и их время, а не слово multiple. Для нескольких проблем intent=multiple, main_symptom содержит ОБЕ проблемы, сохраняется при выборе приоритета.
previous_diagnosis=user_guess для гипотезы, reported_conclusion для чужого заключения, document_quote для цитаты документа. Сама гипотеза/чужое заключение сохраняется в raw_text evidence этого слота, kind=hypothesis/reported_diagnosis. Не размечай предположение как установленную неисправность, main_symptom содержит только наблюдения. known_service только при явном заказе: id из предоставленного каталога. Предположение о детали не означает заказ её замены.
kind только observation,hypothesis,reported_diagnosis,service_request. time_scope только past,current,unspecified. Для сведений об автомобиле/городе используй observation,unspecified. Для заказа intent и known_service — service_request,unspecified. При уточнении intent/слота укажи supersedes предыдущего свидетельства. Если один слот обновляется, прежние данные не должны теряться без явного исправления. Состояние не меняется от вопросов ассистента. Реплика ассистента updates всегда [].
Исправление: пользователь явно признает ошибку; новое значение заменяет старое, ссылка на старую реплику обязательна. Конфликт: несовместимые утверждения об одном факте без разрешения противоречия; итог conflicting с сохранением обеих версий в raw_text. Изменение во времени не conflicting: current_state обновляется, main_symptom сохраняет историю. Не переносить сведения из будущих реплик.
Поведение ассистента: только уточнения, реально меняющие подбор; уже известное не спрашивай. Нельзя требовать технический диагноз от водителя. Можно не знать. Не обещай найденный сервис, запись, цены или наличие. Не ставь диагноз по симптому. Для однозначного заказа не начинай диагностический опрос. Для ключей не подтверждай право собственности: access_proof=user_reported_available только если пользователь сам сообщил о документах. Для специального оборудования уточняй назначение, тип машины или совместимость, когда это влияет на исполнителя.
Весь текст живой русский, допустимы короткие ответы и редкие опечатки. Не используй реальные персональные данные, адреса, телефоны, VIN и госномера. Марки/города допустимы. Выбирай правдоподобную машину, не приписывай ей характеристики, которые пользователь не назвал. Услуги каталога задают направление, не обязательный точный текст. У каждой реплики пользователя разметь ВСЕ явно сообщённые применимые слоты.
Уточнения после пробной проверки: приветствие или просьба помочь НЕ intent=unknown; до сообщения задачи слот отсутствует. Мотор «1.6» НЕ означает petrol; название модели НЕ означает тип силовой установки, нужны слова пользователя о топливе. «На холодную» НЕ означает stationary; это температура, а не движение. stationary только явные «на месте», «на холостом ходу», «пока стоит». Незнание времени начала НЕ current_state=unknown. «Посмотрите систему» НЕ заказ её ремонта, а просьба проверки: не выбирай repair/change вместо diagnosis. Если пользователь говорит «нужна диагностика», выбирай только диагностическую услугу; если подходящего id нет среди предложенных, не заполняй known_service. В main_symptom при уточнении ПОЛНОСТЬЮ сохраняй уже известные симптомы и обе проблемы. Старое описание можно заменить только при явном признании ошибки. Не задавай вопрос «как думаете, в чём причина»: от водителя нужен наблюдаемый симптом, не технический диагноз. Предпочитай называть задачу сразу, а не начинать с пустого приветствия. Не задавай бессмысленный вопрос о выезде для любой обычной работы — формат уточняется лишь когда это меняет подбор.
vehicle_hint и city_hint — подсказки для разнообразия: используй город, а машину только если её исполнение подходит направлению; иначе выбери правдоподобное. Эти скрытые подсказки не становятся фактами до явной реплики владельца. Для электромобиля нельзя писать про свечи зажигания, дизельные форсунки или обычный мотор; для коммерческой спецтехники выбирай соответствующий транспорт. Сценарий должен относиться к заданному разделу по смыслу предлагаемых услуг, а не случайно уходить к общей жалобе.

Компактный формат updates: обязательно только s (слот), q (точная цитата), v (нормализованное значение). Поля k и t можно опустить: скрипт восстановит observation/unspecified; для main_symptom/current_state/observed_context — observation/current; intent=complaint/multiple — observation/current; intent=known_service и known_service — service_request/unspecified; previous_diagnosis=user_guess — hypothesis/unspecified, reported_conclusion/document_quote — reported_diagnosis/unspecified; event — observation/past. Если время или вид источника отличаются от этих правил, ОБЯЗАТЕЛЬНО укажи k/t. supersedes не выводи — ссылки построит скрипт. Содержание и итоговые слоты от сокращения формата не меняются.
Сделай target_turns реплик, заданных в сценарии; заканчивать репликой пользователя допустимо. При target_turns=3 помести задачу и часть сведений сразу в первую реплику, затем один полезный вопрос и ответ. Сложные исправления и изменения во времени можно сделать в 5 реплик даже при заданных 3. Итог ассистента необязателен; не добавляй длинный пересказ всех сведений. Не растягивай все диалоги одинаковым опросом машины и города.
