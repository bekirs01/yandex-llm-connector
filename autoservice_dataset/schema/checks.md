# Проверка первой версии дерева

Дата: 25 октября 2026 года. Метод: ручное прохождение правил и проверка структуры JSON. Диалогового движка и испытаний с реальными владельцами пока нет. Число вопросов относится к уточнениям услуги после начального сообщения; адрес поиска и согласование записи в него не входят.

## Сквозные диалоги

В каждой строке ожидаемый результат сравнивается с ручным путём по текущей спецификации. «Совпало» относится к этому примеру, а не к качеству распознавания произвольного текста будущим ботом.

| Начальное сообщение / продолжение | Ожидаемый результат | Ручной путь и результат | Вопросов; обоснование |
|---|---|---|---|
| «Замените свечи зажигания» | Известная замена свечей | entry_rules → каталог spark-plug-change; совпало | 0: работа известна |
| «Наверное, свечи. Машина плохо заводится» | Диагностика запуска; предположение отдельно | mechanical.entry_rules → mechanical.result.engine; совпало | 0: наблюдение достаточно для выбора диагноста |
| «Свечи надо» → «Сначала проверить причину» | Диагностика, без заказа замены | intent → mechanical.result.engine, если есть жалоба запуска; без жалобы result.complaint с просьбой проверить необходимость работы | 1: намерение меняет услугу; отсутствие жалобы не дополняется выдумкой |
| «Проверьте машину перед покупкой» | Проверка перед покупкой | direct → соответствующая работа каталога; совпало | 0: цель однозначна |
| «Пинается коробка» → «Просто автомат, какой — не знаю» | Сохранить типы коробки до проверки по машине | mechanical.gear → mechanical.result.gear_unknown; совпало | 1: влияет на специализацию; не просить угадывать CVT/робот |
| «С ходовой что-то» → «Не знаю» | Поиск источника шума/общая проверка по доступному описанию | mechanical.chassis → mechanical.result.general; неизвестное не создаёт выдуманную вибрацию | 1: различие не установлено, повторять вопрос нельзя |
| «Спускает шина» | Проверка у шинного сервиса | mechanical.entry_rules → general + компетенция шинного сервиса; совпало | 0: не выбирать биение/ремонт прокола без осмотра |
| «Педаль тормоза стала проваливаться» | Диагностика тормозов; состояние передать исполнителю | mechanical.entry_rules → brakes; совпало | 0: название неисправной детали для подбора не требуется |
| «Кондиционер не холодит» | Диагностика эффективности охлаждения | equipment.climate, cold извлечён из сообщения → equipment.result.climate.cold; совпало | 0: количество хладагента не устанавливается разговором |
| «После удара вмятина на двери и камера парковки не работает» | Кузовной осмотр + диагностика парковочной системы | multi без вопроса → body.damage + safety.park; совпало | 0: обе компетенции известны; не назначать замену камеры |
| «Замените лобовое стекло» | Известная замена; применимость датчиков и калибровок проверяет сервис | direct → замена лобового; совпало | 0: не превращать заказ в опрос о ремонтопригодности скола |
| «Руль тяжёлый, никаких стуков я не замечал» | Проверка рулевого управления/усилителя | mechanical.result.steering с общей проверкой; совпало | 0: не подменять жалобу диагностикой стуков |
| «Сначала сказал, что мотор не прогревается. Ошибся: мотор в норме, в салоне холодно» | Отменить направление двигателя, сохранить климат | corrections → equipment.result.climate.warm; совпало | 0: пересчитать только зависимый результат |
| «Не заводится и заводится — не могу толком объяснить» | Сохранить конфликт, диагностика запуска; текущее состояние неизвестно | engine + current_state=conflicting; совпало | 0 для услуги: обе трактовки дают одного диагноста; при выборе доставки спросить о текущем известном состоянии |
| «Машина исправна, хочу возить велосипеды, крепления ещё не выбрал» | Подбор оснащения по задаче, без диагностики неисправности | equipment.equipment.subject с уже известной целью → equipment.result.equipment.goal; совпало | 0: задача известна; подбор совместимости оставлен исполнителю |
| «Не открывается машина. Нужен мастер на месте» | Выездная помощь по доступу с проверкой права доступа | direct → аварийное открытие, если цель именно открыть; иначе уточнение между открытием и диагностикой доступа | 0 при явном заказе открытия; неоднозначность цели даёт 1 вопрос |

## Лужа: сведения по шагам

Будущее объяснение о намокших клеммах не использовалось при выборе ранних переходов.

1. Владелец: «После лужи машина потеряла тягу и заглохла при трогании». Уже достаточно проверки по жалобе: `mechanical.result.engine`, компетенции диагностики работы двигателя и электрики, событие water. Для выбора стационарного диагноста — 0 вопросов.
2. Если нужен выбор формата помощи и текущее состояние неизвестно, `mechanical.present`: «Каково состояние сейчас — по тому, что уже известно?» Ответ: «Стартер крутил, не заводилась». Это наблюдение о прошлом. Текущее состояние остаётся unknown; вопрос не повторяется. В результате формат помощи требует согласования. Итого 1 вопрос.
3. Позднее сообщение: «Через 30 минут опять завелась». Обновляется текущее состояние; вода и прошедший отказ сохраняются. Диагностика остаётся той же, дополнительных вопросов нет.
4. После результата: «Выяснилось, клеммы намокли и высохли». Это сообщённое объяснение причины. Оно не меняет оснований раннего выбора и не создаёт общего совета ждать высыхания.

Результат совпал с целью сценария: короткий маршрут, изменение состояния сохранено, конкретная деталь не угадана, вопросов о различиях тяги и оборотов нет.

## Что исправлено при сведении

| Найденное слишком узкое решение | Текущий переход |
|---|---|
| Любая проблема колеса → диагностика биения | Общая проверка у шинного сервиса; биение выбирается только при соответствующей жалобе |
| Любое «автомат» → гидромеханическая АКПП | При неизвестном исполнении сохраняются альтернативы |
| Тяжёлый руль → только люфт и стук | Общая проверка с компетенцией рулевого усилителя |
| Прошедшее «не заводилась» → сейчас неподвижна | Прошлое отдельно; текущее unknown до сообщения владельца |
| Уменьшение запаса хода → только батарея | Общая проверка электромобиля, сохранение нескольких направлений |
| Неизвестная сигнализация → только штатный иммобилайзер | Общая проверка с компетенцией штатного и дополнительного доступа |
| Неизвестное дооснащение → диагностика | Уточнение предмета/задачи; затем сохраняемый выбор оснащения |

## Структурная проверка

Проверены: разбор JSON; точное соответствие 394 исходных работ каталогу; уникальность идентификаторов каталога, вопросов и завершений; существование всех названий услуг в результатах; сопоставление названий с service_ids; переходы узлов поддеревьев; обязательные поля вопросов; число вариантов не больше 10. Бытовые входы coverage.md описывают маршруты проверки, а не назначение перечисленного ремонта.

Текстовая сверка по clarity-validator: проверены синтетические утверждения, назначение разделов, согласованность файлов, основания переходов и термины. Исправлены перечисленные выше слишком узкие переходы; автоматические связи «симптом — неисправная деталь» не добавлялись. Ручные проходы явно отделены от испытания работающего бота. Названия исходных работ сохранены; массовой замены терминов с изменением рода/числа не было.

## Нерешённые предметные вопросы

Списки в `mechanical.json:disputed_transitions` и `equipment.json:expert_review` требуют автомобильного специалиста. Основные темы: достаточность общих диагностических услуг, границы проверок рулевого усилителя, запаса хода и последствий воды; протокол ближайшего действия для потенциально опасных обстоятельств; допуски исполнителя для высоковольтных систем, ГБО и коммерческого оборудования. Дерево не предлагает запуск, разборку или опасные проверки владельцу.

Ограничения: список диалогов подготовлен авторами дерева, без независимой пользовательской выборки. Покрытие работ означает достижимость по прямому запросу, а не проверенное распознавание всех синонимов. Утверждение о глобально минимальном числе вопросов не сделано. Следующая проверка — автомобильный специалист и диалоги с владельцами, особенно при неясных целях и противоречиях.
