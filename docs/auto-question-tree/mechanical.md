# Механические системы и низковольтная электрика: разделы 01–13

Структурированное дерево: [mechanical.json](mechanical.json). Это проект подбора исполнителя. Наблюдение не устанавливает неисправность детали. Названия `source_titles` воспроизведены из справочника с точками. Идентификаторы каталога сопоставляются при сборке.

Общий `direct` обслуживает любую названную работу разделов 01–13, включая замену, ремонт, обслуживание, регулировку и технические измерения. Например, «сделайте эндоскопию цилиндров» — известная услуга; «наверное, кольца, машина ест масло» — диагностика расхода масла. Чужое заключение хранится как чужое заключение: «сервис велел заменить сцепление, хочу второе мнение» → диагностика сцепления, «замените по этому заключению» → direct.

Узлы вопросов содержат `id`, `applies_when`, `text`, 2–5 `options`, `slots`, `transitions`, `decision_changed`, `unknown`, `free_text`, `stop`. Уже сообщённое не спрашивается. Результат сохраняет исходную жалобу, все направления, существенные неизвестные и происхождение сведений. Пустой слот допустим. При нескольких жалобах общий `multi` объединяет возможности исполнителя, не предлагает последовательно проходить каждую ветку заново.

## Входы и остановка

- `mechanical.scope` нужен только если направление обращения неясно. Понятный симптом пропускает его.
- `mechanical.gear` различает четыре специализации коробки. Только известное пользователю обозначение гидромеханической АКПП выбирает этот результат; бытовое «автомат» без типа сохраняет альтернативы. «Не знаю» оставляет альтернативы до определения конструкции по данным автомобиля; пользователь не должен угадывать.
- `mechanical.chassis` различает тормоза, руль, подвеску, колёса и неизвестное направление. Одновременно верные ответы разрешены.
- `mechanical.present` используется после отказа только если нужно определить возможность выезда/приёма доставленного автомобиля. Его ответы меняют логистику, но не доказывают причину. В остальных случаях его нужно пропустить. Состояние извлекается из уже известных наблюдений; запускать автомобиль ради ответа нельзя.

Неизвестный двигатель, подозрение на турбину, топливную систему или катализатор не требуют опроса о тонких отличиях оборотов: достаточно проверки по жалобе. Если человек явно называет диагностируемую систему, компетенцию включают в требования сервиса. Комбинированные услуги «диагностика, ремонт или замена» выбираются только с `operation_scope=diagnosis_only`.

Особые границы: жалоба на тяжёлый руль без люфта/стука использует общую проверку по жалобе с компетенцией усилителя. Потеря давления шины без биения также использует общую проверку у шинного сервиса. Нельзя подменять эти жалобы диагностикой люфта или биения только потому, что такие названия есть в каталоге.

### Обязательная лужа: постепенное раскрытие

Начальный доступный ввод: «После лужи машина потеряла тягу и заглохла при трогании». Никаких сведений о клеммах, вращении стартера или последующем запуске на этом шаге нет.

1. По входному правилу уже достаточно `engine`: «Проверка автомобиля по жалобе владельца.», сервис с диагностикой двигателя и электрики. Если задача только подбор стационарной диагностики — остановка, **0 вопросов**.
2. Для подбора с доставкой/выездом появляется единственный допустимый вопрос `present`: «Каково состояние сейчас — по тому, что уже известно?» Пользователь: «Стартер крутил, не заводилась». Сохранить наблюдение о прошлом. Состояние сейчас остаётся `unknown`, формат помощи не установлен: прошлый отказ не означает, что автомобиль неподвижен сейчас. **1 вопрос**, остановка без повторного уточнения; сервису передать эту неопределённость. Не просить ещё раз пробовать запуск.
3. Позже пользователь сам сообщает: «Через 30 минут снова завелась». Обновить current_state=returned, сохранить прошлый отказ и воду, пересчитать логистику. **0 дополнительных вопросов**. Диагностическое направление остаётся engine; состояние не подтверждает исправность.
4. Только после завершённого маршрута раскрывается: «Оказалось, клеммы намокли и высохли». Хранить как сообщённое объяснение с источником. Ни один ранний переход от этой будущей информации не зависит. Не советовать всем ждать высыхания, не назначать замену клемм.

## Спорные переходы

Список `disputed_transitions` находится в JSON. Отвергнуты выводы «лужа → клеммы», «рывки → конкретная деталь», «лампа DPF → регенерация» и «падает давление → ремонт шины». Связь тяжёлого руля с узким названием диагностики люфта требует проверки специалистом; действующий безопасный маршрут использует общую проверку по жалобе и компетенцию рулевого усилителя. Общая диагностика не является разрешением на ремонт детали.
